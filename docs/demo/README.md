# AgentDrop workflow demo

[Watch or download the video](../images/agentdrop-demo.mp4) · [README animation](../images/agentdrop-demo.gif)

A 34-second English walkthrough: Wang asks Codex CLI to send the ablation results to Alice; Alice asks Claude Code
to read them; the same message and its two attachments appear in the web inbox. The GIF is a shorter, silent loop.

This is a staged demonstration with fictional people and data. The agent conversations are illustrations, not
recordings of live model sessions. The web scene mounts the actual `MailboxPage`, session provider, message
viewer and attachment tiles from the product, with a local fixture transport. It opens the actual message row.
The transport has no network fallback, sends no messages, and downloads no attachments. Wang and Alice are
assumed to be contacts already; after Alice reads the message in her agent, the dashboard also shows it as read.

The demo covers sending, requested reading and the web inbox. It does not demonstrate installation, account
pairing, group administration, My space, or a live transfer between two running agents.

## Reproduce

Use the repository's pinned Node/pnpm dependencies, Python 3, FFmpeg (including `ffprobe`), and Google Chrome.
The renderer uses the same Chrome launcher as the browser tests; `E2E_CHROME` can select an existing compatible
Chrome executable. No API credentials, database or running AgentDrop server are needed.

From the repository root:

```bash
pnpm install --frozen-lockfile
pnpm exec tsc -p docs/demo/tsconfig.json
node docs/demo/build.mjs
python3 docs/demo/audio.py
node docs/demo/build.mjs --serve
```

Leave that local preview process running. In another terminal:

```bash
node docs/demo/render.mjs --stills   # inspect frames in tmp/readme-demo/
node docs/demo/render.mjs            # export both files into docs/images/
```

The preview is at `http://127.0.0.1:4391`. Its console exposes `await seek(24)` and `playFilm()`.
The fixed 1920 × 1080 stage is intended for recording. `plan.json` defines the chapters and sound cues;
`main.tsx` composes the film, and `style.css` supplies the framing around the product's own stylesheet.
The renderer checks forward and backward seeks, waits for the message and both attachment names, blocks requests
outside the preview origin, and fails on browser page errors. Intermediate frames, audio and reports stay in the
ignored `tmp/readme-demo/` directory.
