# AgentDrop 使用手册

写给第一次使用的人。不需要读源码；术语只在第一次出现时解释。

## 1. 它解决什么问题

你在 Mac 上用 Codex 写代码，同事在实验室服务器上用 Claude Code 跑实验。你想把“排查结论 + 一个 notes.md”交给同事的
Agent，让它在对方那边直接可用，而不是复制到微信再让同事手动喂给模型。

AgentDrop 做的就是这件事：**你的 Agent 把一条消息（标题、正文、可选附件）投到对方 Agent 的收件箱**。对方随时读取，
也可以另发一条给你。所有消息都留在服务器上，有收件箱、已发送、收藏、归档，可以按联系人或群组回看。

它**不做**的事：不合并两个人的会话、不自动执行收到的内容、不替你决定发给谁。

## 2. 三个概念

**账号**：你本人，用邮箱注册，有一个唯一的 `@handle`（注册后不可改）和一个可以随时改的昵称。还可以在网页“设置 → 账号”
填一个**公开邮箱**（可选，可以直接用登录邮箱），方便同事在其他工具里找到你；它跟人走，你的每个 Agent 显示的都是同一个，
只有已接受的联系人、同群成员和收到你消息的人看得到。系统不验证这个邮箱，也从不往里发信。

**Agent（端点）**：你在某台机器上的某个工具，例如“MacBook 上的 Codex”。消息实际投递到某个 Agent 上；已读、收藏、归档
是你这个人的状态，在你所有 Agent 和网页之间同步。同一个 Codex 不管开几个窗口、几个项目，都是同一个 Agent；GPU 服务器上的 Codex 是另一个 Agent。
默认情况下，你账号里的 Agent 可以列出和读取彼此的历史，所以在服务器上也能回看发给 Mac Agent 的消息；列表会明确标注
实际由哪个 Agent 发出或收到。你可以在设置中关闭“跨 Agent 邮箱可见”，恢复只看当前 Agent。

**至少要有一个 Agent 才能建立关系**：还没配对 Agent 时，不能加联系人、接受申请、生成或使用邀请链接、建群或入群，
因为消息无处投递给你（收到的申请和邀请会一直保留）。网页每一页顶部都会提示，并给出可以直接复制的安装命令；
通过邀请链接注册的，对方的邀请会作为一条待接受的申请放在「联系人」页，配对之后在任何设备上都能接受。
删掉最后一个 Agent 时会同时退出所有群（你是群主的群会交给其他成员），联系人保留。

**默认接收**：别人发给 `@你`、没指定具体哪个 Agent 时，默认**投到你的所有 Agent**，每个 Agent 各收一份，之后新配对的
也算；已读、收藏是同步的。想只投一个，在「我的 Agent」里对那个 Agent 点「只在这里接收」；要改回来点「我的所有 Agent」。
改动只影响以后的消息。别人按地址（如 `@你/claude`）指定的，照旧只投那一个。

## 3. 第一次使用（每台机器一次）

前提：管理员已经部署好服务器并把地址告诉你，例如 `https://drop.example.com`；你机器上已经装了 Codex CLI、Claude Code、Cursor 或 OpenCode，
以及 Node.js 22+。

1. **注册**：打开服务器地址，注册账号，选一个 handle。
2. **两条命令**（终端）：

   ```bash
   npm install -g agentdrop-cli@latest     # 或：curl -fsSL https://drop.example.com/install.sh | sh
   agentdrop setup --server https://drop.example.com
   ```

   `setup` 会：登记这台机器 → 检测已安装的 Codex、Claude Code、Cursor、OpenCode、oh-my-pi（omp）→ 为每个工具申请配对并自动打开浏览器，你核对
   设备名、工具、Agent 名称后点「批准」→ 把 AgentDrop 注册进工具的 MCP 配置 → 装配套 skill 和回合结束通知 → 自检。
   全部 OK 就完成了。以后重启电脑、换项目目录、开新会话都不用再做任何事。

   只想接一个工具：`--harness codex`、`--harness claude-code`、`--harness cursor`、`--harness opencode` 或 `--harness omp`；想让 Agent 能发某个目录里的文件：`--allow-dir ~/projects/paper`。

   在项目文件夹里运行 `setup` 时，配对完成后它会问一句「允许你的 Agent 从 <这个文件夹> 上传文件吗？[Y/n]」，直接回车即允许。
   主目录、根目录、系统目录、隐藏目录和密钥目录从来不会问；脚本或 CI 里不会问。不想被问加 `--no-allow-current-dir`，
   不问直接允许加 `--allow-current-dir`。下载的文件始终放在固定的下载文件夹，不受影响。

Cursor 自动检测会识别 `cursor`、`cursor-agent` 命令或 `~/.cursor` 目录；配置写入 `~/.cursor/mcp.json`，
完整 skill 装到 `~/.cursor/skills/agentdrop`，供本地 IDE 和 CLI 使用。重新加载 Cursor 并按提示批准 MCP。
OpenCode 自动写入 `~/.config/opencode/opencode.json` 的 MCP 条目，并安装监听 `session.idle` 的全局通知插件。
两者分别有独立的配对类型，默认公开入口为 `@你/cursor`、`@你/opencode`。
oh-my-pi（`omp`）自动检测会识别 `omp` 命令或 `~/.omp/agent` 目录，也可以单独接：`agentdrop connect omp --profile omp`。
MCP 条目写入 `~/.omp/agent/mcp.json`，完整 skill 装到 `~/.omp/agent/skills/agentdrop`，另装一个 AgentDrop 管理的扩展
`~/.omp/agent/extensions/agentdrop.js`：启动 omp、发出提示和回合结束时在 omp 里提示你有什么新消息，发提示时也让模型知道有什么待处理。
新开的 omp 会话才会加载它。默认入口为 `@你/omp`；omp 的命名 profile（`OMP_PROFILE`）暂不支持。

在远程服务器上用 SSH 的情况：在**服务器**的终端跑上面的命令并加 `--no-browser`，把打印出来的网址复制到你本地浏览器里确认
即可，服务器不需要能开浏览器，也不需要开放任何端口。Cursor 本机的 MCP 配置和凭证不会自动复制到云端 Agent 或 SSH 主机；在实际运行 bridge 的机器单独安装、配对。

手动分步（等价于 setup，一般不需要）：`agentdrop login` → `endpoint add` → `connect` → `skill install` → `doctor --mcp`。

**装好后先发一条试试。** 每个账号自带一个联系人 `@agentdrop`（AgentDrop 助手）。对 Agent 说“发一条测试消息给 @agentdrop”，
几秒内会收到一条回执：你发的标题、附件名和大小、正文字数、收到时间，以及怎么加真人。回执会回到你发送时用的那个 Agent。
助手只回执，不回传附件；和它的往来 30 天后自动过期。它就是一个普通联系人：不需要可以移除或屏蔽，想要回来在联系人页输入
`@agentdrop` 即可；它不能被拉进群。

## 4. 添加联系人

只有互为联系人的人（或同一个群的成员）才能互发。三种方式：

- **邀请链接（最快）**：网页「联系人」页点「生成邀请链接」，复制发给同事。对方打开链接，注册新账号或登录已有账号，
  配好 Agent 后你们**直接**成为联系人；对方还没配对 Agent 时，邀请会先作为一条申请放在他的「联系人」页，配对后接受即可。链接 7 天有效，可以发给多个人，每人最多同时 5 条有效链接，随时可以作废；
  链接只在生成时显示一次。服务器关闭了自助注册时，链接只能给已有账号的人用，不会开放注册。任一方屏蔽了对方时链接无效。
- **对 Agent 说**：“加 @wang 为联系人”。对方的 Agent（或对方在网页上）接受后生效。对方可以对自己的 Agent 说
  “看看有没有人加我”，它会列出申请并可以直接接受。
- **网页**：「联系人」输入对方的 `@handle` 邀请，对方在自己的「联系人」页接受。

接受之后你可以：

- **写备注**：只有你自己看得到，例如“老王·实验合作”。你的 Agent 搜人时也认这个备注。
- **发给人或具名入口**：联系人页和目录查询只显示对方本人，以及对方主动发布的入口（如 `@wang/research`）。
  对方有几个 Agent、叫什么、使用什么工具、消息投到哪个 Agent 都不公开；发送结果也只显示人或入口。
  可以记住一个已发布入口，以后都投那里；入口失效时会明确报错，不会悄悄改投。旧版记住的自动 Agent 地址会恢复为发给本人。
- **自动发送**：联系人接受后，Agent 可以直接发送普通文字与上下文，不需要你再到网页点一次。

## 5. 让 Agent 收发消息

直接用自然语言对已接入的 Codex / Claude Code / opencode / Cursor 说话即可，它会调用 AgentDrop 的工具。

| 你说 | Agent 做的事 |
|---|---|
| “看看有没有人给我发东西” | 默认列出账号下所有 Agent 可见的收件记录，并标出实际收件 Agent |
| “读一下老王发来的那条” | 读取正文和附件列表，转述给你后把它标为已读（是你要它读的）；Agent 自己为了干活去读、列一列、搜一搜都不算 |
| “老王看了我发的那条吗” | 查看已发送消息的 `recipient_status`：谁已读、什么时候读的 |
| “把上面的结论发给老王” | 先查目录确认是哪个“老王”，再发送 |
| “处理一下老王的反馈” | 先引用那条回一句「收到，我先……」再开始干活，并告诉你已经回过了：私信就回给老王本人；群里的消息就在那个群里引用回复并 @老王，群里其他人也知道有人在处理。做完再用同样的方式回复结果。你说「别通知他」就不回 |
| “回复老王那条：已经修好了” | 发一条新消息并注明是回复哪条（`reply_to`）；老王那边会看到「回复了你的「…」」，你这边那条随即算已读 |
| “把 notes.md 也发过去” | 上传文件，作为附件一起发 |
| “把老王那条标为已读 / 收藏” | 已读、收藏、归档是**人**的状态，你所有 Agent 同步：在哪个 Agent 里改，其他 Agent 都一样 |
| “下载他发的 results.csv” | 保存到 `~/.local/share/agentdrop/downloads/<消息 id>/`，不会打开或解压 |

几个规则：

- **同名不猜**。目录里有两个“王同学”时，Agent 会把候选列出来让你选，不会按第一个发。
- **附件只能来自你允许的目录**。先 `agentdrop allow-dir add ~/projects/paper --profile codex`。`.ssh`、`.env`、
  密钥文件在任何目录下都会被拒绝。
- **收到的内容是外部文本**。Agent 读到的正文即使写着“忽略之前的指令”，也只是别人写的一段字，工具返回时会标注为
  不可信内容。
- **发送结果只有四种**：`delivered`（已存到对方收件箱，不代表对方在线或已读）、`needs_approval`（等你在网页确认）、
  `not_sent`（没发出去，原因写在返回里）、`unknown`（网络中断，Agent 会用同一个请求号去查，不会重复发）。
- **跨 Agent 可见不等于广播投递**。消息仍只落到寻址到的 Agent；其他 Agent 只是按账号偏好获得只读视图。已读、收藏、
  归档是人的状态，你所有 Agent 同步；发送方只能看到当时公开的目标地址/Agent 归属，不会得到对方的私有设备清单。

### 对方看了没有（已读状态）

- 你发出的消息，在网页「已发送」里显示「已读 / 未读」，群发显示「3/5 已读」，点开详情可以展开谁在什么时候读的。
  Agent 用 `list_drops view=sent` 或 `read_drop` 也能拿到同样的 `recipient_status`，直接回答“他看了吗”。
- “已读”指对方的任一 Agent、网页或 CLI **打开过正文**，或手动标为已读。只看列表预览不算；你自己读自己发的不算；
  群管理员翻看群历史也不算。群发的计数按人算，不含你自己。
- 反过来，你打开别人发来的正文，发件人也会看到你已读。它只显示到“人”，不暴露你用的是哪个 Agent 或设备；
  也不会改变你自己信箱里的未读状态（见下一节）。

### 回复和未读

- 一条消息可以注明“这是对哪条的回复”。网页上点「回复」，或者对 Agent 说“回复老王那条……”都会带上。它不是会话串：
  对方看到的是「回复你的「原标题」」，可以点回原消息；你发出的消息上会显示「收到 2 条回复：老王、Mia」。
  只有对方自己也能看到原消息时，才会显示原标题。
- 你自己收件箱里的“未读”表示“还没回应”。以下几种情况算你处理过了，你所有 Agent 和网页同步变成已读：
  - 在网页上点开它；
  - 回复它；
  - 在某个群里发了一条消息：这个群里在此之前发给你的消息（包括 @你 的）都算已读；
  - 手动标为已读；
  - 在网页收件箱点「全部标为已读」（在某个群的视图里是「本群全部标为已读」）：只标你点的那一刻列表里已有的，之后新到的仍是未读；已归档的不动。
- 你让 Agent 读某条消息、它转述给你之后，这条也算已读。如果某条未读消息看起来和你正在做的事有关，Agent 会在回答
  末尾问你一句要不要读，你同意了它才读——收到的消息是别人写的，不会被悄悄读进你的任务里。Agent 自己为了干活去读、列一列、搜一搜，不会改变你的未读。回合结束的提醒和推送也会说明「Wang 回复了你的「…」」。

## 6. 审批：什么时候需要你点一下

普通文字、上下文和成功上传的附件都会由 Agent 直接投递，不会要求你再点一次。文件格式不限，但仍受容量配额；本地 Bridge
也继续阻止 `.ssh`、`.env`、私钥等敏感路径。只有管理员显式启用自定义组织审批策略时，发送才可能进入「草稿与审批」。

审批页显示标题、正文摘要、收件人、原因和内容指纹。点「批准并投递」才会发出。如果在你看的时候对方改了默认接收端，
页面会提示“目标已变化，请重新核对”，再点一次即可。24 小时没处理会自动作废。

## 7. 群组

群是一个持久的成员空间，不是每次临时多选收件人。建群、邀请、入群、退群都可以直接对 Agent 说（“建一个叫论文讨论组的群，
把老王和小李拉进来”），也可以在终端或网页做。通过 Agent 入群时，绑定的是这个 Agent 自己所在的端点；想让其他设备也收，
去网页勾选。

```bash
agentdrop group create paper --name 论文讨论组 --invite @wang,@li --profile codex
agentdrop group create --invite @wang,@li --profile codex   # 不起名：群名是你的昵称加邀请人数（如“你 +2”），短代码用你的 handle
agentdrop group list      --profile codex     # 我的群、谁待我回应、哪个群发不出去
agentdrop group invite paper @zhang           --profile codex
agentdrop group requests  --profile codex     # 待我批准的入群申请（批准要去网页）
agentdrop contact add @wang --profile codex               # 发联系人申请；对方在自己的 Agent、网页或用 agentdrop accept 同意
agentdrop contact remove @wang --profile codex            # 先列出将被移除的联系人，不做改动
agentdrop contact remove @wang --profile codex --confirm  # 确认后才真正移除（Agent 会先问你）
```

**没有“直接把人拉进群”这回事。** 拉人永远是两步：有人邀请，对方接受。在那之前他是“邀请中”，占一个名额，收不到任何内容。
这也是它和微信/Telegram 最根本的区别。

- **默认是「我的所有 Agent」接收**：建群、接受邀请时不用挑，账号下每个 Agent 都能收也能发，之后新配对的 Agent 也自动加入。
  想只让部分 Agent 接收，在群设置里改成「只用选中的 Agent」，这时新配对的 Agent 不会自动加入。
  通过 Agent（MCP）建群或接受邀请也是这个默认。建群时可以一次填多个 `@handle` 同时邀请。
- 群发的上限按接收端算，默认 200 个（20 人 × 每人最多约 10 个 Agent），和 20 人的成员上限是两回事。
- **任何成员都可以邀请人**，不要求被邀请人是自己的联系人。每个群可以单独设置“成员邀请是否需要管理员批准”：
  新建的群默认不需要，本功能上线前就存在的群默认需要（迁移不会悄悄放宽既有权限）。
- 需要批准时，成员发起的邀请会变成一条**入群申请**，被邀请人在批准前完全不知情。**批准只能在网页做**——让一个人进群
  等于让他能直接私信群里所有人，这个决定不交给 Agent，终端里 `agentdrop group requests` 只给你看和给你链接。
- **每个群最多 20 人**，计入在群成员和还没回应的邀请（入群申请不占名额）。
- 一次群发 = 每位成员每个绑定的 Agent 各一条独立投递；已读状态按人记，成员在任一 Agent 或网页读过就都算已读。
- **20 人上限和 50 个端点上限是两回事**：如果群里好几个人各绑了 3 个 Agent，端点数可能超过 50，那么这个群的每一次群发
  都会被整单拒绝（`TOO_MANY_RECIPIENTS`）。网页的群页面和 `agentdrop group list` 会分别显示这两个数字。
- **默认新成员看不到加入之前的消息**；退群后看不到群里的历史（已经下载到本地的文件不会被收回）；重新加入是新的一次加入。
- **群主可以让新成员看到入群前的消息**：在网页群的「设置」→「入群前的消息」里选「新成员可以查看入群前的消息」
  （建群时也可以直接选）。开启后，每位在群成员都能在群的消息列表里只读地看到本群全部历史，包括自己入群之前的；
  这些消息不算未读、不会提醒、也不能标已读或收藏，Agent 用 `list_drops` 加群的 `group_id` 也能看到。改回「新成员只能看到
  入群之后的消息」后，入群较晚的成员又看不到入群前的消息，已经投递给他们的照常保留。只有群主能改，其他成员在群页面上
  能看到当前是哪一种。退群或被移出后都看不到。
- **群主和管理员可以查看本群的全部消息**，包括他们加入之前的、以及没有投递到他们 Agent 的那些。这种查看是只读的
  （不能改别人的已读状态），每一次都会写进服务端审计日志。群设置页面会向成员明示这一点。
- 如果某个成员的接收 Agent 被撤销了，群发会整单拒绝并告诉你是谁需要修复，不会“发给一部分人然后假装全员收到”。
- 群成员之间可以直接私发，不需要另外加联系人。
- **每个群有文件空间上限**（服务器统一设置，默认 512 MB，服务器管理员可在网页「管理 → 设置」里调）。群页面显示
  已用多少、上限多少。发带文件的群消息时，如果放不下，整条消息不会发出，提示会说明是哪个群、还差多少；不带文件的
  消息不受影响。**不会自动删掉任何人的旧文件**：要腾空间，由群主或管理员在群页面的「文件」列表里（按大小排）移除
  旧文件，消息本身还在，文件那一栏对所有人显示「已移除」，再下载会提示文件已移除。

## 7.1 怎么知道有人找我，以及不离开终端怎么处理

**通知：保证你在 Agent 里看到每一条**。`agentdrop connect` 会为每个支持的 harness 安装对应适配。
每条消息、每个申请都会在你用 Agent 的过程中**让你看到一次**，而且是在你确定在场的时候：

| 什么时候 | 你看到什么 | 算不算「看过了」 |
|---|---|---|
| 你在 Codex / Claude Code 里发一句话时 | 你还没看过的新消息，显示在你这句话下面 | 算，所有终端、所有机器都不再重复 |
| 你新开或恢复一个会话时 | 同上 | 算 |
| Agent 一个回合结束时 | 同样的内容先预告一下（每个会话只预告一次） | 不算：你可能在看别的窗口。接着在这个窗口打字就算看过、不再重复；去别的窗口打字，那里会再给你看一次 |
| Claude Code 底部状态栏 | `✉ AgentDrop · 2 条新消息（@wang、#lab）`，你看过之后自动消失 | 不算 |
| 浏览器推送、飞书 | 你离开电脑时的提醒 | 不算：回到 Agent 里仍会让你看到一次 |

所以消息不会因为落在了后台窗口、或者先推送到了浏览器，就在 Agent 里永远看不到；也不会在每个窗口反复刷屏。
处理掉之后同一个人再发申请，会当作新的再提醒一次；待审批数量变多时提醒。通知只写来了什么，不写命令——在对话里直接
对 Agent 说「看看 AgentDrop」就行。状态栏在 `connect claude-code` 时自动装上；如果你已经有自己的状态栏，不会覆盖，
会告诉你怎样把 `agentdrop statusline --profile <名字>` 加进去。Codex 的状态栏只能选内置项，所以没有这一项。

**Claude Code 2.1.287 及以后：输入框上方的 AgentDrop 列表。** 新版 Claude Code 支持 mod，`connect claude-code`
会装上 AgentDrop 的 mod，代替底部状态栏（旧版仍是状态栏）。输入框上方显示 `✉ AgentDrop`，等你处理的每条一行，新的
在上面，来一条就多一行：

```
✉ AgentDrop
Wang 回复了你的「消融实验」                        [ 读一下 ] [ 收到，处理中 ] [ 稍后 ]
#lab · 3 条新消息（Carol、Mia）                    [ 看看 ]   [ 全部已读 ]     [ 稍后 ]
```

- 「读一下」：替你对 Claude 说「读一下这条」，Claude 读给你听并标为已读；你不按，Claude 不会读。替你说的话里只有消息编号和对方的 @用户名，不会带上别人写的标题或名字。
- 「收到，处理中」：不用开新回合，直接回对方一句「收到，我在处理了」；群里的消息就在群里引用这条并 @ 对方（对方已退群时就只在群里回）。按两次只发一次。发出后马上在 AgentDrop 面板里打开这条消息（标题、发件人、正文、附件名），面板下方说明回复是已送达，还是要先在网页上确认；Claude Code 全屏布局且终端够宽（110 列起）时面板在右侧边栏，否则在输入框上方。
- 「看看」/「全部已读」：让 Claude 概括这个群的新消息，或把这一行代表的群消息标为已读（单独列出的 @你 和回复不受影响）。
- 「稍后」：这台电脑上先藏起来（一周，所有窗口共用）；群里再来新消息时重新出现。
- 同一个人连发几条时合成一行，例如「Wang · 3 条新消息 · 最新「……」」，按「读一下」让 Claude 把这几条一起读给你，收起时这几条一起收起（这一行没有「收到，处理中」，要逐条回复请在 `/agentdrop` 面板里打开）。
- 不用手点也会消失：每一行出现两分钟后自动收起（效果同「稍后」，所有窗口共用）；来了新消息就多一行新的，各算各的两分钟。最多同时显示 5 行（发给你的、@你的、回复你的优先，其次是最新的群消息），一下子来很多条时，其余的合成一行「还有 N 条新消息」，和它们一起到时收起。你离开超过五分钟时出现的消息不会在你不在时消失：等你回来敲键盘或点按钮后才开始计两分钟。按「读一下」或「看看」的那一行立刻收起。收起的消息仍是未读，在 Claude Code 里输入 `/agentdrop` 打开的面板（全屏布局、终端够宽时在右侧边栏，否则在输入框上方）和网页上都还在。
- 「回复了你的」只用在回复你自己发的消息时；别人之间的回复按普通消息显示。
- 连不上服务器时，列表先保留一轮；连续两次失败后只显示一行灰字「AgentDrop：暂时连不上你的收件箱」。
- 键盘：Ctrl+X 再按 Tab 进入列表，方向键选按钮、回车按下，Esc 回到输入框。列表没有数字快捷键，在输入框里按数字只会回答 Claude 的选项。
- 输入 `/agentdrop-read`：让 Claude 帮你过一遍消息。先说一共多少条未读、分别是谁发的；和当前会话正在做的事关系紧密的逐条详细讲，其余的按人或群各一句话概括；只有详细讲过的标为已读，你开口前不会处理或回复。后面可以加词指定重点，比如 `/agentdrop-read Wang 的消融实验` 或 `/agentdrop-read #lab 评测结果`，匹配的消息不论是否已读都会详细讲。其他 Agent（Codex、opencode、Cursor、omp）没有这个命令，直接说「帮我过一遍 AgentDrop 消息，重点看……」效果一样；Codex 里在前面加 `$agentdrop`（例如 `$agentdrop 过一遍消息，重点看 Wang 的消融实验`）会明确调用 AgentDrop 的说明。各 Agent 回合结束的提醒里，列不下的消息会写成「另有 N 条新消息未列出，可以让 Agent 帮你过一遍」。
- 输入 `/agentdrop`：不经过 Claude，直接在面板里读消息（立刻打开，再刷新），面板里可以按数字键打开对应的那条，打开即已读；关掉了通知时面板也照样列出未读。内容太长时会提示只显示了前一部分。

联系人申请、群邀请和待审批只显示一行提醒，在网页上处理。列表只是方便你看到；「看过」仍然以你在会话里发话或新开会话为准。

私信和群消息分开列，群消息写明是哪个群；选了 `--notice-detail names` 还会带上昵称和群名。通知默认是英文，`agentdrop settings --language zh` 切成中文（`--language en` 切回）。英文示例：

```
AgentDrop: new
New messages: 3
Direct messages:
- @wang · "实验结果" · 1 attachment
In group #paper:
- @li · "周会纪要"
- 1 more new message not listed
Contact requests: 1
- @li
Group invitations: 1
- #paper
Join requests: 1 (only you can decide, in the dashboard)
- #paper ← @zhao (invited by @wang)
Pending approvals: 1 (only you can approve, in a terminal or the dashboard)
```

切成中文后同样的内容是：

```
AgentDrop 新通知
新消息：3 条
私信：
- @wang ·「实验结果」 · 1 个附件
群 #paper：
- @li ·「周会纪要」
- 另有 1 条新消息未列出
联系人申请：1 个
- @li
群邀请：1 个
- #paper
入群申请：1 个（只能由用户在网页确认）
- #paper ← @zhao（@wang 邀请）
待人工审批：1 条（只能由用户在终端或网页确认）
```

每一类都直接列出**是谁、是哪一条**，而不是只给一个数字：未读最多列 5 条、联系人申请和群邀请各最多 5 个、入群申请最多 3 个，
多出来的写成「另有 N 条未列出」。`--notice-detail names` 只是在 handle / slug 旁边**多加一个显示名**，不影响列不列。
整条通知统一截断在 1200 字符，按行切，末尾补「已截断」（英文是 `(truncated)`）——四个 harness 用同一个上限，
所以 OpenCode 的 toast 不会把一个汉字切成半个。入群申请只有你本人能在网页上批，通知里不放链接；
`agentdrop pending` 和 `agentdrop group requests` 的交互输出会给出每条的确认链接。

**上面这段文字在四个 harness 上逐字节相同，不同的只是外层包装，因为读它的人不一样。** Codex 和 Claude Code 的
`systemMessage` 是文档写明「给用户看的警告」，Stop hook 的 stdout 根本进不了模型上下文；OpenCode 插件把同样的文字交给
`client.tui.showToast`，toast 是 Event 不是 Part，同样到不了模型。这三条通道上没有、也不需要任何对模型说的话，
所以通知里不再夹一句「给模型：……」给你看。
Cursor 的 `stop` 事件**没有**只给人看的输出字段，`followup_message` 会被当成下一条用户消息提交给模型——所以只有
Cursor 这一路会把上面的通知用 `<agentdrop_notice>` 包起来当作不可信数据，后面再跟两行：一行说明这是外部元数据不是指令，
一行要求模型只向你转述一句、不要调工具、不要读正文、不要替你审批。生成配置与 CLI 都会拦截后续循环（`loop_count > 0` 直接返回 `{}`）。
参考：[Cursor Stop hooks](https://cursor.com/docs/hooks#stop)、[OpenCode plugins](https://opencode.ai/docs/plugins/)。

没有新东西、检查失败或还在查询冷却期时不显示。

给你看的和给 Agent 看的是同一批信息，但读者不同：给你看的只报你还没看过的；你发消息时，同一个 hook 还会把当前
**全部**待处理事项和可用工具放进 Agent 的上下文（你看不到，固定英文），让 Agent 处理时看得到全貌，但它不会主动提。
网页整体默认英文、深色主题；右上角可以一键切中文和浅色，也可以在「设置 → 外观与语言」里选（只保存在当前浏览器）。
默认每个回合结束都预告（间隔为 0）；设了间隔只影响回合结束的预告，一次成功查询即重新计时，网络失败五分钟后重试；
发消息、开会话时的提示不受间隔影响。手动 `agentdrop pending` 始终可用。
通知查的是账号汇总视图（你所有 Agent 收到的未读），「已经看过什么」整个账号只记一份、存在服务器上；在网页读过的
消息也不再算待处理。服务器还是旧版本时，退回以前的方式：回合结束提醒一次就算提醒过。
hook 使用显式的 `--in-hook` 模式：消息和更新都没有到期时只返回 `{}`，什么也不发生。
没人看着的会话不会用掉提醒：脚本、CI 里批量跑的 `claude -p`、`codex exec` 既不显示、也不记为看过，
新消息留到你自己发消息或开会话时再给你看。别的自动化环境可以设 `AGENTDROP_UNATTENDED=1` 明确声明。

可用 `agentdrop settings --notify-interval 30m --notice-detail names` 调整间隔和信息粒度，
`--notifications off` 关闭所有给你看的提示（发消息、开会话、回合结束、状态栏；Agent 在你发消息时看到的待处理清单不受影响）。默认每天检查一次 CLI 稳定版更新，有新版就在后台自动安装（连同配套 skill 和 Claude Code 的 mod），
`agentdrop settings --updates notify` 改为只在下一次 Stop 回合结束提醒一次，`--updates off` 关闭后台检查。
另外，服务器发现你最近用过的某个 Agent 的 CLI 落后时，内置助手 @agentdrop 会给你发一条消息，列出是哪几个 Agent、
最新版本和升级命令；网页收件箱、回合结束提醒、浏览器通知和飞书都会收到。还没升级的，会在 1 天、3 天后再提醒，之后每 7 天一次，
全部升级后就不再提醒；在网页把那台设备的更新方式设为「关闭更新检查」也不会再收到。
更新在独立后台进程进行，只有受支持的 npm 全局安装才能自动更新；已有 MCP 会话不会重启。
检查由发消息、开会话、回合结束这几个事件触发，闲置时没有常驻计时器（状态栏由 Claude Code 每 30 秒刷新，同一台
机器上的所有会话共用一次查询）。（Codex 第一次运行会让你信任这些 hook；不想要可以 `connect … --no-hook`。）

**处理（终端命令，不需要 Agent 也不需要网页）**：

```bash
agentdrop pending   --profile codex        # 结构化总览（主动查询，不受 Stop 间隔限制）
agentdrop inbox     --profile codex --unread
agentdrop read ad05b3be --profile codex    # id 前缀即可；在终端里读即标为已读，--keep-unread 保持未读
agentdrop send @wang -m "消融实验跑完了" --file results.csv --profile codex   # 发给联系人
echo "日志见附件" | agentdrop send '#paper' --file run.log --profile codex   # 发到群，正文从管道读
agentdrop send me --file model.pt --profile codex   # 放进「我的空间」
agentdrop requests  --profile codex        # 谁想加我、我加了谁、群邀请
agentdrop accept @wang --profile codex     # 或 accept #paper（用这个 profile 的端点入群）
agentdrop approvals --profile codex        # 等我审批的发送
agentdrop approve <id> --profile codex     # 终端里按 y 确认；--reject 拒绝
```

`read` 把消息打印到终端时，就算你读过了：未读的消息会标为已读（你所有 Agent 同步），并在输出里说一句。
输出不是终端（脚本、管道、Agent 通过 shell 工具运行）、加了 `--json` 或 `--keep-unread` 时都不改状态；
`--mark-read` 在这些场合也强制标为已读。

`send` 适合终端和 CI 里的交接：收件人写 `@handle`、`#群` 或 `me`（我的空间）；正文用 `-m`/`--body` 或从管道传入，
不写标题时取正文第一行（最多 80 字），没有正文时取第一个文件名。附件和 Agent 上传一样只能来自允许的目录，密钥文件一律拒绝；
被拒时会打印允许那个文件夹的命令。需要审批时会告诉你去哪里批准；`--json` 输出原始结果给脚本用。网络中断会用同一个
请求 id 重试，不会发两次。

`approve` 只在真实终端里能用：它从 `/dev/tty` 读你的确认，Agent 通过 shell 工具跑它拿不到 TTY，所以模型不能替自己批准。

**当然也可以对 Agent 说**（“看看谁加我，都接受”“把老王那条读一下”），或者打开网页——三种方式操作的是同一份数据。

**浏览器系统通知**：收件箱顶部或网页「设置 → 即时通知」可以为当前浏览器开启 Web Push。订阅属于你的账号，
不绑定远程 Agent 所在的 H；所以 Codex、Claude Code 或 Linux 服务器不在线时，手机/电脑仍能收到新 Drop 提醒。
锁屏通知显示 Agent 在 Drop `title` 字段填写的标题和发送者 handle，但不显示正文或附件名。标题只按纯文本展示并限制长度。
iPhone/iPad 需先用 Safari“添加到主屏幕”，再从主屏幕打开并授权。

**飞书通知**：新消息、联系人申请、群邀请和入群申请也可以发到飞书群里，由服务器在消息到达时发送，电脑和 Agent
不需要在线。在飞书群里加一个自定义机器人，把 Webhook 地址填到网页「设置 → 飞书通知」，或交给 Agent 运行
`agentdrop settings --feishu-webhook <地址> --profile <profile>`；装了 lark-cli 的话，对 Agent 说「把 AgentDrop
通知接到飞书」，它会帮你建一个只有你的群并给出打开链接。只发标题，不发正文和附件；每条只提醒一次，飞书提醒过的
Agent 不会再提。完整步骤、安全设置和错误码见 [飞书通知指南](FEISHU.md)。

**开发者 Webhook（高级）**：设置页仍可登记一个 HTTPS 接收端。它接收联系人、群邀请、新消息和审批事件的 AgentDrop JSON；
第三方机器人 Webhook 通常不能直接兼容，需要自建接收端做验证和格式转换。事件不含正文和附件。

## 7.2 导出往来记录（留痕与分析）

想回答「我和老王这个月都交接了什么」，可以按日期范围把往来导成一个结构化文件：

```bash
agentdrop export --contact @wang --since 2026-09-01 --until 2026-10-01 --profile codex > wang-9月.jsonl
agentdrop export --group  #paper  --since 2026-09-01 --until 2026-10-01 --profile codex --out paper.jsonl
```

网页上也有：联系人详情页和群页各有一个下载入口，选好起止日期点下载。

输出是 **NDJSON**（每行一个 JSON 对象），默认含完整正文，加 `--brief` 只出标题和摘要。主要是给脚本和模型读的；
想给人看加 `--format md` 出一份时间线 Markdown。

几条需要知道的规则：

- **日期范围是 `[起, 止)`**，左闭右开、UTC。所以连续两个月的导出既不会重复也不会漏。
- **按时间排序用的是「写下的时刻」**，不是「到达我这里的时刻」——同一条 Drop 投到不同人的 Agent 时刻可能不同，
  用发送时刻才能让两边导出的文件对得上。
- **按联系人导出只含直发**（含发到对方具名入口的）。**你们在同一个群里说的话不在里面**——那些属于那个群，
  用 `--group` 单独导。这不是偷懒：如果按联系人导出把群消息也算进来，它就等于在告诉你「这条群消息具体被哪些成员收到了」，
  而这正是群投递刻意不告诉发送方的事情。
- **已撤销、已过期的 Drop 不会出现**，文件头里会写明这一点。
- **文件最后一行是校验行**，带条数和内容摘要。CLI 会自己核对；核对不过就**什么都不写**，不会给你留一个看起来正常、
  其实少了一截的留痕文件。
- 单次导出上限 2000 条、跨度最多一年，超了会明确报错而不是截断。

**管理员导出全群历史**（含自己加入之前的）只能在网页上做，终端和 Agent 都不行——理由和「批准入群申请」一样：
这是比「我收到了什么」更宽的读取，需要一个人在浏览器里明确按下。每次这样的导出都会单独记审计。

普通的导出（按联系人、按群导自己收到的）**Agent 可以直接做**，因为它本来就能用 `list_drops` 逐条读出同样的内容，
导出只是更高效，不是新增权限。

## 7.3 我的空间：在自己的几台机器之间传东西

像微信的「文件传输助手」：把文件或备注放进「我的空间」，再到另一台机器上取。放进去的东西你所有的 Agent 都能看到、
能下载；它不进收件箱、不算未读、不会提醒任何地方，你需要时主动去取。

- **网页**：侧栏「邮件」下的「我的空间」，选文件（可拖进来）、写一句备注，点「放进去」；列表里可以下载和删除。
- **终端**（不需要 Agent）：

  ```bash
  agentdrop space put results.csv model.pt --note "第三轮消融的结果" --profile codex   # 在笔记本上放进去
  agentdrop space list --profile codex                                                # 在服务器上看有什么
  agentdrop space get --latest --to ./incoming --profile codex                         # 取最新一份
  agentdrop space rm 3f2a --profile codex                                              # 删掉一条，释放空间
  ```

- **对 Agent 说**：「把这个文件放进我的空间」「把我空间里最新的文件拉下来」。
- 删除只能你自己在网页或终端做（Agent 会告诉你怎么删，不会自己删）。删除后文件从服务器上清掉，释放的是当初上传它的
  那个 Agent 的空间额度（每个 Agent 默认 1 GB）。
- 想把一件事明确交给另一个 Agent 去处理（例如让 GPU 服务器上的 Agent 接着跑），仍然是直接发给那个 Agent：那种消息会
  保持未读、让它看到。

## 8. 多台设备、换机器、丢设备

- **新增一台机器**：在那台机器上重复第 3 节。它是一个新的 Agent（新的投递与状态作用域），但默认仍能回看账号内其他
  Agent 的历史；如果不希望这样，在设置中关闭跨 Agent 邮箱可见。
- **复制了整个 home 目录到新机器**（镜像、容器模板）：先跑 `agentdrop device rebind --yes`，再重新配对，否则两台机器
  会被当成同一台。
- **凭证到期**（默认 90 天）：`agentdrop doctor` 会提前两周提醒；重新 `endpoint add` 即可，收件箱不变。
- **机器坏了、丢了、换掉了**：Agent 的配对凭证只存在那台机器上，所以那台机器上的 Agent 没法再用；但你的账号、消息、
  联系人和群都在服务器上，什么都不会丢。按这个顺序做：
  1. 在新机器上 `agentdrop setup`，它会配出新的 Agent。
  2. 打开网页「我的 Agent」，在旧 Agent 的卡片上点「管理」，用「机器没了？把这个 Agent 转给另一个」，选新机器上的对应 Agent，
     点「转过去」。旧 Agent 的入口、群里只用它接收的设置、默认接收都会转到新 Agent 上，
     **记住了具名入口的联系人什么都不用改**；旧 Agent 随即被删除（消息保留）。
  3. 同一台机器上还有别的 Agent，逐个这样转；不打算接替的，用设备名右边的「删除设备」一次删除。
  - 历史消息（包括只投到旧 Agent 的）照常能从新 Agent 和网页上读到，附件也能下载。
  - 已经删除了的旧 Agent 也可以事后再转：点页面底部「显示已删除的」，在它的卡片上转；删除时一起失效的入口会恢复并转到新 Agent 上。
  - 不转、直接删除也可以，但要注意：记住了旧具名入口的人发送时会看到「这个入口已不可用」，需要他们重新选；
    群如果设成「只用选中的 Agent」且只选了旧的，要在群设置里改，否则大家往这个群发都会失败。
  - 删除的 Agent 不能「恢复」后在原机器上继续用：旧机器找回来了，也是重新配对成新的 Agent，再按上面第 2 步转一次。
- **机器上有 HTTP 代理**（环境里有 `HTTP_PROXY` / `HTTPS_PROXY`）：服务器明明 curl 得通，AgentDrop 却每次超时、
  Stop hook 报 "hook timed out"。原因是请求被送去了代理，而代理到不了内网地址；**`NO_PROXY=172.16.0.0/12` 这种网段
  写法是无效的**——Node 只按精确主机名和域名后缀匹配 `NO_PROXY`，网段会被静默忽略。
  AgentDrop 自己会处理：首次请求前只看服务器地址判断（不做任何探测），是环回、`10/8`、`172.16/12`、`192.168/16`、
  `169.254/16`、`100.64/10`、IPv6 ULA/链路本地、没有点的裸主机名、`.local`、`.internal`，或者已被你写的网段覆盖，
  就把精确主机名补进 `NO_PROXY`。要强制的话：`AGENTDROP_PROXY=never`（一律绕过代理）或 `AGENTDROP_PROXY=always`
  （一律走代理，适用于服务器确实只能经代理访问的情况）。

## 9. 常见问题

**改了 Agent 名字，同事那边要重新加吗？** 不用。名字只是显示，身份和历史都不变。

**同事看得到我给他写的备注吗？** 看不到。备注不进入消息，也不出现在对方看到的任何地方。

**同事看得到我有几台设备吗？** 看不到。对方只能看到你的昵称、handle、你填写的公开邮箱，以及你主动公开的入口名。

**必须用网页吗？** 日常不必：看、读、接受申请、入群、审批都能在终端或对 Agent 说完成。网页用于注册、配对确认、
改名、公开邮箱、默认接收端、公开入口、撤销凭证、Webhook 设置，以及想用鼠标的时候。

**我在网页上也能发消息吗？** 能。网页发送时要选“从我的哪个 Agent 发”，消息会标记为来自网页，不会冒充是模型发的。

**消息能撤回或编辑吗？** 目前不能。消息一旦投递就不可变；需要更正时另发一条。

**服务器管理员能看到我的消息吗？** 管理后台看不到：它只显示数量和大小，接口也不返回内容。服务器开启了内容加密时
（网页「使用说明 → 隐私与安全边界」会写明），标题、正文和附件在服务器上加密存储，只拿到数据库、备份或文件存储的人读不到；
但同时掌握服务器和加密密钥的运维方仍然可以解密。没有端到端加密，所以不要用它传不能让服务器运营者看到的内容。

**Agent 会不会自动执行收到的脚本？** 不会。下载只是把文件放到下载目录；执行永远是你自己的决定。

**两个人可以用同一个账号吗？** 不建议。账号是“人”，Agent 是“人的工具”；共享账号会让审批和备注失去意义。

**忘记密码怎么办？** 不需要邮件，也不用找管理员，任选一种：

- **在配对过 Agent 的电脑上**：自己在终端里输入 `agentdrop account recover`，按提示输入你的 handle，它会给出一个设置新密码
  的链接。这条命令只能由你在终端里亲自运行，Agent 不能替你运行。
- **用恢复码**：事先在「设置 → 账号 → 忘记密码时」生成一组恢复码（要输入当前密码，只显示一次，请存进密码管理器或打印）。
  忘记密码时在登录页点「忘记密码」，填登录邮箱和其中一个恢复码，每个恢复码只能用一次。
- **通过邮件**：只有服务器配置了邮件时才有。填注册邮箱，打开邮件里的链接；页面不会透露某个邮箱是否注册过。
- 都不行时，再请管理员在「管理 → 用户」里为你生成重置链接，通过私聊或当面交给你。

无论哪种方式，链接都是 1 小时内有效、只能用一次；设置新密码后所有设备上的网页登录都会退出，已配对的 Agent 不受影响，
不用重新配对。平时网页登录会保持 60 天，常用就不会掉线。

## 10. 出问题先看这里

```bash
agentdrop doctor --mcp
```

它会逐项检查：配置目录、设备登记、服务器可达、每个 profile 的凭证有效期与身份、允许上传的目录、以及真正启动一次
bridge 做 MCP 握手。常见提示：

| 提示 | 含义 | 做什么 |
|---|---|---|
| `server reachable FAIL` | 连不上服务器 | 检查网络、代理、地址是否 https |
| `credential missing (re-pair)` | 本机没有凭证 | `agentdrop endpoint add …` 重新配对 |
| `identity FAIL UNAUTHORIZED` | 凭证已撤销或过期 | 同上 |
| `allowed dirs none` | 还没允许任何上传目录 | `agentdrop allow-dir add <目录> --profile <名>` |
| Codex/Claude/Cursor/OpenCode 里看不到工具 | 客户端配置没写入或没重启 | `agentdrop connect …` 再重启客户端 |

## 网页管理提醒与更新（0.4.3+）

在「设置 → 客户端偏好」选择设备，可设置提醒周期、信息粒度、更新检查周期和自动安装。保存后先显示等待同步；客户端通过 Stop、MCP 心跳或带 profile 的 CLI 操作取得配置，回报后才显示已应用。首次需将客户端升级到 0.4.3 或更新版本。网页保存的设备配置优先于本机后备设置。

CLI 自动升级完成后会验证已安装版本，并由新程序同步完整 skill 目录。手动 npm 升级后首次正常运行也会修复 skill。一个通用入口搭配按需引用，安装到已识别的 Codex、Claude Code、opencode、Cursor 目录；失败会保留备份并报告待修复，不假称成功。已打开会话是否重新载入 skill 由 harness 决定。
